# Zavod — сайт студии

Готовый статический сайт для студии разработки сайтов **Zavod**. Чистый HTML/CSS/JS, без сборки, без npm — можно открыть локально или опубликовать на GitHub Pages.

## Структура файлов

```
/
├── index.html      — вся разметка страницы
├── style.css       — все стили
├── script.js       — вся логика (меню, модалки, форма, FAQ и т.д.) + блок CONFIG
├── robots.txt      — для поисковых роботов
├── sitemap.xml     — карта сайта для Google
└── README.md       — этот файл
```

## 0. Дополнительный файл: test.js

`test.js` — необязательный QA-скрипт (Playwright), которым проверялась работа сайта: меню, модалки, FAQ, форма, отсутствие горизонтальной прокрутки на 320/375/430px и т.д. Для сайта и GitHub Pages он не нужен — на сам сайт никак не влияет и не подключён из `index.html`. Можно оставить в репозитории как задел на будущее или просто удалить.

Запуск (если понадобится): `npm install -D playwright && npx playwright install chromium`, затем `python -m http.server 8123` в одном терминале и `node test.js` в другом.

## 1. Как открыть сайт локально

Просто откройте `index.html` в браузере двойным кликом — сайт полностью статический и не требует сервера.

Если хотите открыть через локальный сервер (иногда удобнее для проверки):

```bash
# Python 3
python -m http.server 8000
# затем откройте http://localhost:8000
```

## 2. Что обязательно изменить перед публикацией

Все контактные данные собраны в **одном месте** — в начале файла `script.js`, в объекте `CONFIG`:

```js
const CONFIG = {
  telegramUrl: 'https://t.me/your_username',
  telegramLabel: '@your_username',
  phoneHref: 'tel:+380000000000',
  phoneLabel: '+380 XX XXX XX XX',
  emailHref: 'mailto:hello@example.com',
  emailLabel: 'hello@example.com',
  instagramUrl: 'https://instagram.com/your_instagram',
  instagramLabel: '@your_instagram',
};
```

Измените значения — и они автоматически подставятся в блок «Контакты» и в футер.

Дополнительно вручную проверьте и замените:

- **`index.html`** — тег `<link rel="canonical">` и все `og:url` — впишите свой будущий адрес вида `https://ваш-логин.github.io/`.
- **`robots.txt` и `sitemap.xml`** — замените `https://your-username.github.io/` на ваш реальный адрес.
- **Название бренда**, если захотите изменить — встречается в `<title>`, логотипе шапки/футера и текстах раздела «О нас».
- **Цены** — в текущей версии сайта цены не указаны намеренно (в FAQ сказано, что стоимость обсуждается индивидуально). Если захотите добавить конкретные цифры — впишите их в карточки услуг (`index.html`, раздел `#services`) и/или в ответ на вопрос «Сколько стоит сайт?» в разделе FAQ.
- **Демонстрационные проекты** (`#works`) — когда появятся реальные кейсы, замените текст карточек и модальных окон (`modal-work-1` … `modal-work-5`) на настоящие проекты, а вместо кнопки-заглушки «Открыть проект» добавьте реальную ссылку (`<a href="...">` вместо `<button data-demo-link>`).
- **Отзывы** (`#reviews`) — сейчас это демо-отзывы с пометкой «Демо-отзыв». Замените текст и уберите бейдж `badge--demo`, когда появятся настоящие отзывы клиентов.
- **Политика конфиденциальности** — модальное окно `modal-privacy` в `index.html` сейчас содержит текст-заглушку. Если сайт собирает данные через форму заявки, замените его на настоящую политику.

## 3. Что сейчас работает в демо-режиме

- **Форма заявки** (`#request`) — валидирует поля и показывает сообщение «Форма работает в демонстрационном режиме…», но **никуда не отправляет данные**, потому что у сайта нет backend. В `script.js`, в функции `initForm()`, есть подробные комментарии с тремя вариантами подключения реальной отправки:
  1. **Formspree** — самый простой вариант, не требует своего сервера.
  2. **EmailJS** — отправка письма напрямую из браузера через их SDK.
  3. **Свой backend / Telegram-бот** — если хотите принимать заявки в свой Telegram или CRM.
- **Кнопка «Открыть проект»** в карточках демонстрационных работ — показывает всплывающее уведомление о том, что это демо-проект без отдельной ссылки, вместо перехода на несуществующую страницу.

Всё остальное (меню, плавная прокрутка, модальные окна услуг и работ, FAQ-аккордеон, кнопка «наверх», анимации появления при прокрутке) работает полностью, без доработок.

## 4. Как опубликовать на GitHub Pages

### Шаг 1 — создать репозиторий на GitHub

1. Зайдите на [github.com](https://github.com) и войдите в свой аккаунт (или зарегистрируйтесь).
2. Нажмите **New repository**.
3. Введите имя репозитория, например `zavod-site` (или `ваш-логин.github.io`, если хотите получить адрес без названия репозитория в пути — см. шаг 4).
4. Выберите **Public**, не добавляйте README (он уже есть) и нажмите **Create repository**.

### Шаг 2 — загрузить файлы

Вариант А — через веб-интерфейс (без терминала):
1. На странице пустого репозитория нажмите **uploading an existing file**.
2. Перетащите все файлы: `index.html`, `style.css`, `script.js`, `robots.txt`, `sitemap.xml`, `README.md`.
3. Нажмите **Commit changes**.

Вариант Б — через git в терминале:
```bash
git init
git add .
git commit -m "Первая версия сайта"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/zavod-site.git
git push -u origin main
```

### Шаг 3 — включить GitHub Pages

1. В репозитории откройте **Settings → Pages**.
2. В разделе **Build and deployment → Source** выберите **Deploy from a branch**.
3. Выберите ветку `main` и папку `/ (root)`.
4. Нажмите **Save**.
5. Подождите 1–2 минуты — GitHub покажет ссылку вида `https://ваш-логин.github.io/zavod-site/`.

### Шаг 4 — получить адрес вида `username.github.io` (необязательно)

Если хотите, чтобы адрес сайта выглядел как `https://ваш-логин.github.io/` без названия репозитория:
1. Назовите репозиторий **именно** `ваш-логин.github.io` (это специальное имя для GitHub Pages).
2. Загрузите туда те же файлы и включите Pages так же, как в шаге 3.

## 5. Как добавить сайт в Google Search Console

1. Зайдите на [search.google.com/search-console](https://search.google.com/search-console).
2. Добавьте ресурс — выберите тип **«Префикс URL»** и укажите адрес вашего сайта (например `https://ваш-логин.github.io/`).
3. Подтвердите права: самый простой способ для GitHub Pages — метод **HTML-тег**: Google даст вам строку `<meta name="google-site-verification" ...>` — вставьте её в `<head>` файла `index.html` и опубликуйте изменения, затем нажмите «Подтвердить» в Search Console.

## 6. Как отправить sitemap и запросить индексацию

1. В Search Console откройте раздел **Файлы Sitemap** (Sitemaps) в левом меню.
2. Введите `sitemap.xml` и нажмите **Отправить**.
3. Чтобы ускорить индексацию главной страницы: откройте инструмент **Проверка URL** (URL Inspection), вставьте адрес главной страницы и нажмите **Запросить индексирование** (Request indexing).

Индексация обычно занимает от нескольких дней до пары недель — это нормально для нового сайта.
